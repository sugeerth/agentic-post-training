The core

A training loop that closes

Fixed pipelines run stages and stop. Here, the policy that collects each round's data is the policy the previous round improved — expert iteration with a supervisor in the loop. Decisions are grounded in fresh environment probes, never the training curve. 

   ┌──────────────────────────────────────────────────────────┐
   │                                                          │
   │   collect(policy skill s) ──▶ curate ──▶ train ──▶ s'    │
   │        ▲                                           │     │
   │        └──────── next round collects with s' ──────┘     │
   │                                                          │
   │   probe  s' on fresh env rollouts   ← ground truth     │
   │   audit  reward vs measured success (hacking check)     │
   │   decide continue / adjust / rollback / stop —          │
   │          and the decision patch mutates the next round   │
   └──────────────────────────────────────────────────────────┘
🎯

Goal-driven termination

Runs until the target success rate is met, the rollout budget is spent (checked before each round), or improvement genuinely plateaus. Never "ran out of stages."

🛠️

Real interventions

Supervisor decisions carry config patches the loop applies: KL tightening (hard-capped), rollback to the best checkpoint, exploration boosts. Escalation is bounded — a broken run stops early instead of thrashing.

🔬

Probe-grounded decisions

Every decision reads fresh environment rollouts at the updated policy, never the optimizer's own loss curve — the discipline that catches reward hacking.

The crew

Every agent owns one hard problem

All agents are registry-built — swap any specialist with one decorator, zero pipeline edits.

🧭

Supervisor

Picks the recipe from your goal, monitors every stage, and intervenes — continue / adjust / rollback / stop — with patches that actually apply.

🛤️

Trajectory Curator

Rolls out multi-turn tool-use episodes against a real step-based environment, then rejection-samples the set the trainer sees.

⚖️

Reward Model

Fits outcome or process reward models and reports calibration (ECE) alongside accuracy — mis-calibration is where hacking starts.

🏋️

Agentic Trainer

Trajectory-level updates with credit assignment across turns and KL control against a reference agent policy.

🕵️

Reward-Hacking Detector

Spearman ρ between reward and measured success, plus a gap check — ten lines of auditable math, deliberately not a learned model.

🥊

Bake-off Agent

Runs recipes head-to-head and picks the winner under a KL ceiling, with the pareto frontier of success vs drift.

📝

Reporter

Attention-budgeted TL;DR: six lines above the fold, sparkline curves, deltas vs the last run, one next action. Anomalies only.

📚

Paper Scout

Daily arXiv scan extracts new technique names and claims, then generates runnable stub files for bake-off comparison — reviewed via draft PR.

📈

Evaluator

Benchmark suite with baselines, per-benchmark deltas, and concrete recommendations — terse by design.

Use cases

What people actually do with it

From solo research to team CI — the same pipeline, different entry points.

01

Prototype a post-training recipe before renting GPUs

Sketch the full pipeline — curation, RM, RL update, eval — against the seeded simulation environment. Validate the orchestration, intervention thresholds, and reporting before a single GPU-hour is spent. Swap in a real trainer via the registry when you're ready.

→ RL researchers · ML engineers
02

Bake off techniques head-to-head

GRPO vs trajectory-DPO vs rejection-sampling FT on the same tasks, same budget, same eval. Winner picked under a KL ceiling so a recipe that "won" by drifting off-distribution doesn't ship.

→ teams choosing a training strategy
03

CI/CD for training pipelines

Every push runs the pipelines and posts one TL;DR comment on the PR — all plans, sparkline curves, deltas vs the last run. The autonomous loop runs as a CI job and fails the build if the policy stops converging.

→ anyone reviewing training changes in PRs
04

Catch reward hacking before it ships

The detector rank-correlates reward against measured task success each round. Reward up while success is flat triggers a rollback to the best checkpoint and a KL tighten — automatically, with the decision logged.

→ alignment & safety reviewers
05

Regression detection across runs

Every run persists to history. The reporter shows per-metric deltas vs the last run of the same plan, and a >5% success regression flips the next action from "ship the checkpoint" to "revert or investigate."

→ teams iterating on a recipe over weeks
06

Stay current with the literature, automatically

A daily job scans new arXiv abstracts on agent post-training, extracts technique names and claims with auditable regex (not an unsupervised LLM), and opens a draft PR with runnable stubs — a human reviews before merge.

→ research leads · reading groups
07

Teach RL post-training without a cluster

The whole stack runs in seconds on a laptop: students watch credit assignment, KL control, curation quality, and intervention logic play out in readable logs and sparkline curves — no GPU, no API keys.

→ courses · workshops · self-study
08

Build your own specialist

Register a custom trainer, reward model, environment, or supervisor under an existing role — one decorator, no fork. The message bus, reporting, and CI integration come for free.

→ framework extenders · plugin authors
Techniques

Classic + agentic + auto-generated

Single-turn techniques for base LLMs, trajectory-level techniques for agents, and daily auto-generated stubs from the literature.

TechniqueTierWhat it does
PPO / GRPO / DPO / RLHF / SPOcoreSingle-turn post-training staples — GRPO value-free (DeepSeek-R1 style)
KTO / ORPO / RLAIF / SPIN / SimPO / IPOcoreAdvanced & experimental preference methods
multi_turn_grpoagenticGRPO where the "response" is a whole trajectory; group-relative advantages across rollouts
trajectory_dpoagenticDPO over (winning, losing) rollout pairs — no reward model needed
rejection_sampling_ftagenticSTaR-style: sample K, keep successes, fine-tune, repeat
process_reward_modelagenticStep-level rewards for long-horizon tool use
expert_iteration (autonomous loop)agenticThe closed collect→train→probe loop with supervisor decisions
techniques/mimics/*autoDaily-generated stubs from new arXiv papers, pending human implementation
Honesty note: the numbers on this page and in the demo come from a seeded simulation environment — a deterministic tool-use world built so the orchestration, auditing, and reporting layers can be developed and tested without GPUs. The framework's training interfaces are real; plug in your own models, environments, and compute to produce real results.
