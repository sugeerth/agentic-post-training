Behavior evals for agentic models

Find the failure. Prove the fix. Decide what ships.

Small, deterministic environments for coding, tool use, long-horizon tasks, instruction following and calibrated factuality. Every change gets a hypothesis, paired confidence intervals and a three-rule ship gate. Every failure becomes training data.

About these numbers. The shipped experiments use SimulatedPolicy, a test double that replays reference solutions and injects known defects at set rates. They show that the graders, statistics and gate work end to end. They say nothing about any real model. Plug in a real one with CallablePolicy.
The loop

From a vague behavior problem to a ship decision

One YAML file per hypothesis. The same artifacts come out of every run, so any result can be audited and reproduced from its manifest.

Hypothesize

Write what should change and where: targets: [factuality].

Run

Baseline and candidate act in every environment, over several seeds and the same tasks.

Grade

Deterministic graders give each failure a stable tag: missing_arg, hallucination…

Gate

Paired bootstrap Δ per environment yields SHIP, HOLD or BLOCK. The exit code works as a CI gate.

Train

Failures become preference pairs: chosen = reference, rejected = model output. These feed DPO, ORPO or KTO.

Experiments

Three hypotheses, three verdicts

Each run compares a baseline and a candidate across all five environments. Pick one to see how the gate reached its decision.

Environments

One file per behavior

Each environment implements three methods (tasks, respond, grade) and runs through one shared episode loop. Single-turn function calls and 8-step tool chains go through identical code.

Readiness gate

A gate you can recite

The rules apply per environment, to the paired difference candidate − baseline on the same items. Pairing removes per-item difficulty from the variance, which matters when eval sets are small.

BLOCK

Any environment regresses significantly: Δ < −max_regression and the whole CI is below zero.

HOLD

A target environment fails to clear the bar: Δ < min_gain or the CI touches zero. Add tasks or seeds, or rethink the fix.

SHIP

Every target improved with CI > 0 and nothing regressed. The candidate is ready to go into the next major run.

Use it

Run it on a real model in two files

Any function from Observation to Action is a policy: an HF checkpoint, a vLLM server, an API, or a full production agent harness.

my_model.py
# a policy is just a function
from evals import Action, Observation, ToolCall

def act(obs: Observation) -> Action:
    reply = call_your_model(obs.prompt, obs.tools, obs.history)
    if reply.tool_call:
        return Action(tool_call=ToolCall(reply.name, reply.args))
    return Action(text=reply.text, confidence=reply.confidence)
experiments/my_run.yaml
name: my_run
hypothesis: New checkpoint improves tool use
  without regressing instruction following.
targets: [function_calling, multistep_tools]
baseline:  {kind: callable, target: "my_model:act_v1"}
candidate: {kind: callable, target: "my_model:act_v2"}

# $ python -m evals run experiments/my_run.yaml
# → runs/my_run/report.md   exit 0 SHIP · 1 HOLD · 2 BLOCK
